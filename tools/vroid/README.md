# アバターの立体モデルを用意する

立体のアバターを、球や円柱を積んで作るのはやめた（`tools/blender/` 参照）。
どれだけ調整しても基本形の寄せ集めに見え、人が彫ったモデルには届かない。
**VRoid Studio で作って VRM で書き出し、ゲームはそれを読む**。

- VRoid Studio: <https://vroid.com/studio>（無料 / Windows・Mac）
- 出てくる `.vrm` は glTF なので、three.js がそのまま読める
- ボーン名が規格で決まっているので、ゲームの姿勢をそのまま流しこめる

置き場所は `public/` の下。**上から順に探して、最初に見つかったものを使う**。

    public/avatar.vrm   VRoid Studio。表情・一人称・揺れもの が入っている ← いま使っているもの
    public/avatar.glb   ふつうのリグ付き glTF（Tripo の自動リグ・Mixamo・Blender）

置いていなければ、今までどおり基本形のアバターが出る（ゲームは止まらない）。

## 背丈の合わせかた（読むときに1回だけ）

**背の高さ**を `REST_CROWN`（55.4px ≒ 1.414m）にそろえる。目の高さでは
そろえない。平らな絵は2頭身で目が身長の 71% にあるが、人の形のモデルは
89% ほどなので、目でそろえると体が children サイズまで縮んで家具と
釣り合わなくなる。

VR のカメラのほうを、**モデル自身の目の高さ**（`VrmAvatar.eyeY`）へ動かす。
VRM は目の位置を持っている（`lookAt.offsetFromHeadBone`）。

## かならず要るもの: **ボーン（リグ）**

歩く・すわる・手をふる をさせるので、**人型のボーンが入っていること**が条件。
入っていないモデル（画像から起こしただけのもの）は、置いても
**立ったまま滑って動く**だけになる。

ボーン名の流儀（VRM・Mixamo・Blender・その他）は問わない。
`src/vr/humanoid.ts` が名前を見分けて合わせる。要るのは次の15本:

    hips / spine / chest / neck / head
    左右の upperArm / lowerArm
    左右の upperLeg / lowerLeg / foot

8本以上そろっていれば姿勢を当てる。足りなければ立たせたままにする
（`VrmAvatar.posable`）。

## 置いたら確かめる

    npm run dev
    → http://localhost:5173/tools/vroid/check.html

読めたか・背の高さ・**姿勢を当てられるか**が出て、4つの姿勢
（立ち・歩き・すわり・手をふる）を並べて描く。
4体が同じかっこうなら、ボーンが入っていない。

## 画像から起こす道具（Tripo など）を使うとき

書き出すときは次を確かめる。

| | |
|---|---|
| リグ | **自動リギングをかけて書き出す**こと。かかっていないと姿勢が当たらない |
| ポーズ | **T ポーズか A ポーズ**。手を顔に当てた・脚を組んだ形だと、自動リグがうまく入らない |
| マテリアル | 体ぜんぶが1枚だと、きせかえの色が効かない。肌・髪・服・くつで分かれているのが望ましい |

### 置けない形式

| | なぜ |
|---|---|
| `.vroid` | VRoid Studio の**編集用プロジェクト**。中身は VRoid 独自の protobuf で、モデルの形式ではない。VRoid Studio から **VRM を書き出す**こと（下の「2. 書き出す」） |
| `.obj` | 骨も、皮の付きかた（ウェイト）も持てない形式。置いても立ったまま滑る |
| `.fbx` | 骨は持てるが、ブラウザがそのまま読めない。`.glb` に変換すること |

置けるのは `.vrm` と `.glb` だけ。

### 直してから置く（2手）

自動リギングの書き出しは、そのままでは壊れていることが多い。
**Tripo のものは2か所とも壊れていた。** 次の2つを順に通す。

    python3 tools/vroid/fix_rig.py  もと.glb   なおした.glb
    python3 tools/vroid/reskin.py   なおした.glb public/avatar.glb

| 道具 | 直すもの |
|---|---|
| `fix_rig.py` | **骨の位置**。骨格を `inverseBindMatrices` にだけ入れて、ノード側を原点に潰したまま出てくる。骨格ぜんたいの向きがメッシュとずれている（Y まわりに 90 度）のもここで直す |
| `reskin.py` | **ウェイト**。どの頂点がどの骨に付くか。Tripo のものは腕の頂点の7割が腰に付いていた。骨の線分までの距離で配り直す |

どちらも「直すまえ／あとのずれ」を出すので、0 になっていれば直っている。
直さずに置くと、腕を動かしたところから**引きちぎられる**。

### きせかえの色

マテリアルの**名前**を見て掛ける（`skin` `hair` `tops` `bottoms` `shoes`
などの語を探す）。名前に手がかりが無い1枚ものだと、どの色も乗らない。

# VRoid Studio で作る

---

## 0. みほんを出す

VRoid に読ませる**モデルのデータは無い**（`.vroid` を作る手立てがないため）。
渡せるのは「どんな見た目にするか」の資料だけ。
キャラクターはすでにゲームの中にいるので、それを並べた みほん を出せる。

    npm run dev
    → http://localhost:5173/tools/vroid/sheet.html

髪型10種・ふく4種・肌5色・髪7色・ふく8色 が並ぶ。
ゲーム本体と同じ絵の出しかた（`src/render/avatarPreview.ts`）で描いているので、
絵を直せばこの資料もついてくる。

VRoid では、この中から**髪型ひとつ・ふくひとつ**を選んで作る
（VRM 1ファイルに1種類しか入らないため）。色はきせかえで変わる。

## 1. 作る

VRoid Studio で新規作成 → 顔・髪・体・衣装を作る。ふつうに作ってよいが、
このゲームで効くところだけ挙げる。

| 項目 | どうするか | なぜ |
|---|---|---|
| 身長 | **気にしなくてよい** | 読みこむとき、目の高さが 39.6px（≒1.01m）に来るよう自動で縮める。部屋も家具もその背丈で作ってある |
| 髪 | 揺れもの（スプリングボーン）は付けてよい | VR で歩くと自然に揺れる。こちらで毎フレーム更新している |
| 衣装 | **明るい色・白っぽい色**にしておく | きせかえの色を **掛け算** で乗せる。元が濃いと色が変わらない |
| 肌 | 既定のままでよい | 同上。きせかえの肌色が掛かる |
| 表情 | プリセット（`happy` `sad` `angry` `relaxed` `surprised` `blink`）を残す | ゲームの7表情をここへ割りあてている |
| 瞳・口 | 色は自由 | きせかえの対象外。さわらない |

## 2. 書き出す

「撮影・エクスポート」→「エクスポート」→ VRM。設定は次のとおり。

| 設定 | 値 | なぜ |
|---|---|---|
| ポリゴン削減 | **有効**（既定のまま） | Quest / スマホでも動かしたい |
| ボーン数削減 | 有効 | 揺れものを間引く。見た目はほぼ変わらない |
| マテリアル数削減 | **有効** | 描画回数が減る。VR は 90fps 出したい |
| テクスチャアトラス | **1024** か 2048 | 4096 だと配信が重い |
| VRM 形式 | 1.0 でも 0.x でもよい | どちらも読める |

書き出したファイルを `public/avatar.vrm` に置いて、**コミットする**。
GitHub Pages は リポジトリの中身をそのまま配るので、置いただけだと
手もとでしか出ない。

### 大きさの目安

**8MB 以下**に収めたい。超えるならテクスチャアトラスを 1024 に落とす。
GitHub Pages から配るので、初回に落ちてくる量がそのまま待ち時間になる。

なお `.vrm` は Service Worker の先読み一覧（`src/pwa/precache.ts`）には
**入れていない**。VR に入ったときに初めて取りにいく。

## 3. 確かめる

    npm run dev

ブラウザで開いて VR ボタン。鏡の前に立つと自分のすがたが映る。

- 出ない → ブラウザの Network タブで `avatar.vrm` が 200 で返っているか
- カメラが胸のあたりにある → 目の位置が VRM に入っていない。VRoid の
  書き出しなら必ず入っているので、別のツールで作ったファイルを疑う
- きせかえの色が変わらない → 衣装の色が濃すぎる。掛け算なので、
  黒い服には何を掛けても黒いまま

## いまできていないこと

**髪型10種・ふく4種の切り替えは、VR では効かない。**
VRM 1ファイルには髪型もふくも1種類しか入らないため。
色（肌・髪・シャツ・ズボン・くつ）は掛け算で効く。

増やすなら、いまのところ次のどちらか。

1. 髪型・ふくごとに VRM を書き出し、`avatar-hair3-dress.vrm` のように
   並べて、きせかえに合わせて読みかえる。配信量は増える
2. 素体は同じまま、髪と衣装のメッシュだけを別 VRM から抜いて差し替える。
   VRoid の同じ素体から書き出したファイルはボーンがそろうので、
   `SkinnedMesh` の付けかえで足りる。1ファイルあたりの追加は小さい

どちらも作りは決まっているので、必要になったら足す。

## ゲーム側のつくり

| ファイル | 役目 |
|---|---|
| `src/vr/vrmSource.ts` | `public/avatar.vrm` を1回だけ取ってくる。無ければ `null` |
| `src/vr/vrmPose.ts` | 紙人形の姿勢 → 人型ボーンの角度。three を読まないので単体で試せる |
| `src/vr/vrmAvatar.ts` | VRM 1体。背丈合わせ・色・表情・一人称の頭隠し |
| `src/vr/avatar3d.ts` | 外向きの顔。VRM が来たら基本形と入れかえる |

紙人形の姿勢（位置で作る）を関節の角度に読みかえるところが要。
厳密には一致しないので、「立ち・歩き・すわり・手を上げる」の4つが
平らな絵と同じに**見える**ところへ係数を寄せてある（`vrmPose.ts`）。
